# 홈커밍 파티 스릴러 구현 명세서 v2

Nov 7, 2026 · v1(Nov 6, @유리)에 플레이 피드백과 구현 중 결정을 반영한 개정판. 아래 v2.1에서 받은 에셋과 추가 기믹을, v2.2에서 플레이 피드백을, v2.3에서 난이도 조절(맵·카메라 축소, DM 주기, 레벨 0~2, 문, 사람 종류)을, v2.4에서 메뉴·종료·일시 정지 UI를, v2.5에서 파티 분위기 디자인을, v2.6에서 플레이 피드백(사람끼리 겹치지 않기, 따라오기 멈춤, 레벨 0을 테스트 맵으로, 인원 2배, 소품 재사용 대기 표시)을, v2.7에서 레벨 9개·맵 3종·방별 인원 나누기·반응 점수 감소·새 무한 모드를, v2.8에서 답장 난이도(긴 단어와 문장, 촘촘한 글자 풍선)를, v2.9에서 DM 빈도 상한(레벨 5), 무한 모드 인원 증가, 방 단위로 모으는 플레이리스트, 조명 아래 춤추기를, v2.10에서 UI 개편(만화 스타일, 화면 글자 영어)을 반영했습니다. v2.7\~v2.9(A)와 v2.10(B)은 동시에 작업해 병합했습니다.

A는 시스템과 탑뷰를, B는 휴대폰 뷰와 UI·연출을 맡으며, 두 파트는 `GameState` 오토로드로만 통신합니다. v1은 코드를 문서에 모두 실었지만, 이제 코드가 저장소에 있으므로 v2는 규칙, 구조, 계약, 수치를 기준으로 삼습니다. 코드와 이 문서가 다르면 이 문서를 고치거나 팀에 알립니다.

> **검증 상태:** v2.9는 Godot 4.7.2 헤드리스 자동 테스트(레벨별 DM 주기, 플레이리스트가 모으는 범위, 춤추기, 무한 모드 40명)와 창 모드 캡처·프레임 시간 측정으로 확인했습니다. v2.8은 Godot 4.7.2 헤드리스 자동 테스트(레벨별 글자 풍선 간격 각 80회, 문장 입력과 끄고 켜기, 레벨 1·4·6·9 입력 봇 90초)와 창 모드 휴대폰 화면 캡처로 확인했습니다. v2.7은 Godot 4.7.2 헤드리스 자동 테스트(9레벨 각 100\~120초, 레벨 1\~9 연속 진행, 무한 모드 이동·레벨 업·상한)와 창 모드 화면 캡처(새 맵 2종, 무한 모드)로 확인했습니다. v2.6은 Godot 4.7.2 헤드리스 자동 테스트(레벨 1·2에서 각각 300초, 따라오기 빈도는 900초)와 창 모드 화면 캡처로 확인했습니다. v2.4 UI는 Godot 4.7.2 창 모드 자동 테스트로 메뉴부터 게임, 종료, 재시작까지의 흐름을 확인하고 화면을 캡처해 봤습니다. Godot 4.7.2 창 모드에서 `main.tscn`을 실행해 자동 테스트로 v2.1 기믹을 확인했습니다. v2.3은 Godot 4.7.2 헤드리스 자동 테스트로 레벨 0~2, 문, DM 주기, 글자 간격, 사람 종류를 확인했습니다(화면 모양은 미확인). 사람과 플레이어 위치는 테스트가 직접 배치했으므로, 실제 조작으로 플레이하며 확인해야 할 항목은 마지막 절에 따로 적었습니다.

### 공동 작업 규칙

- **파일 소유권:** 상대 파트의 파일은 직접 고치지 않고 요청합니다. `game_config.gd`는 예외로, 각자 표시된 구역의 값만 수정합니다.
- **통신:** 파트 간 직접 참조를 금지합니다. `GameState`의 시그널과 메서드만 사용하며, 시그니처 변경은 상의 후 진행합니다. `main.gd`는 세 씬을 묶는 역할만 합니다.
- **수치와 배치:** 밸런스 수치는 `GameConfig`에만 둡니다. 노드 배치, 크기, 색, 글자 크기 같은 모양은 각 씬(`.tscn`)에서 편집합니다.
- **문법:** Godot 4.3 이상, GDScript, 정적 타입을 사용합니다. 들여쓰기는 공백 4칸이며 파일 안에서 탭과 섞지 않습니다. Godot 에디터의 들여쓰기 설정(Editor Settings → Text Editor → Behavior → Indent → Type)을 Spaces로 맞춥니다.
- **씬:** 탑뷰, 휴대폰, UI를 각각 씬으로 나눕니다. 동적으로 생기는 것(NPC, 알파벳 버튼)만 코드에서 씬을 인스턴스합니다.
- **범위:** 이 문서에 없는 기능은 추가하지 않습니다. 애매한 부분은 가장 단순하게 구현하고 `# TODO(확인필요):`를 남깁니다.

| 무한 모드 | v2.7. 방 없이 상하좌우로 끝없이 이어진 바닥. 사람과 소품은 플레이어 둘레 1920×1440 구역 안, 화면 밖에서 생기고, 구역에서 멀어지고 화면 밖이면 사라짐. 소품은 한 번 쓰면 효과가 끝난 뒤 사라짐(재사용 대기 없음). 게임 시간 1시간(180초)마다 레벨이 오르고 시계는 멈추지 않음. 180초가 지나도 승리하지 않고 발각이나 DM 10단계로 끝날 때까지 점수를 쌓음. 히든 엔딩은 없음 |
| 일시 정지 | 게임 진행 중 ESC. 시간, 사람, 휴대폰이 모두 멈춤. 휴대폰이 켜진 상태도 유지됨 |
| 따라오는 사람 | 옵션이 켜진 사람은 37.5초마다 최대 8초 따라옴. 반응을 충분히 받은 사람도 최대 8초 따라옴. 플레이어(144px/s)보다 느린 108px/s. 80px 안에 들어오면 그 자리에 멈추고 따라오기를 끝냄(v2.6). 80px는 발각 반경과 같아서, 휴대폰을 켠 채 따라오는 사람이 도착하면 발각됨 |
| 반응 | 300px 안의 사람을 클릭. 왼쪽은 긍정, 오른쪽은 부정. 같은 사람에게는 0.5초에 한 번. 사람마다 3\~7회 무작위로 정해진 횟수를 채우면 따라옴. 점수는 같은 사람에게 반응할수록 줄어들고(10, 5, 2, 1, 0), 그 사람에게 마지막으로 반응한 뒤 20초가 지나면 다시 10점부터 |
| 길막 | 걷는 사람의 앞을 몸으로 막으면 사람이 멈춤. 0.6초 막으면 기록, 3초 막으면 넉백(약 150px) 후 3초 행동 불가. 행동 불가 중에는 이동, E, 반응, 휴대폰 켜기 불가 |
| 숨은 입력 | 휴대폰이 켜져 있을 때 키보드나 글자 버튼으로 L을 3번 연속 입력하면 "L을 가져가", B-A-J-I를 연속 입력하면 "바\~지" 음향 효과. 다른 글자가 끼면 무효 |
| 둥글게 둥글게 | 모든 사람(레벨 1\~9: 10\~26명)이 길막 기록이 있는 상태에서 휴대폰을 켰다 끄면 사람들이 주인공을 둘러싸고 바라봄(3초), 공포 효과(1.5초) 후 히든 엔딩으로 종료 |
| 슬로우 댄스 타임 | 60\~100초 사이 무작위 시각에 25초 동안. 느린 음악이 나오고 사람들은 제자리 ±48px 안에서 28.8px/s로만 움직임. 소품 어그로와 이미 시작된 따라오기는 그대로 동작 |
| 점수 | 답장: 100 − 15 × (단계 − 1), 최소 10. 반응: 같은 사람에게 처음 +10, 다시 반응할 때마다 절반(내림)으로 5, 2, 1, 0. 마지막 반응 뒤 20초가 지나면 다시 +10부터. 길막 기록 1회 +10. 춤 1회 +150. 오답 1회 −10. 0점 아래로는 내려가지 않음 |
| 휴대폰 전환 | 켜고 끄는 판정은 입력 즉시 적용되고 전환은 화면 효과만. 켜는 즉시 발각 판정이 시작되고, 끄는 즉시 이동할 수 있음. 내려가는 도중 다시 켜면 그 자리에서 다시 올라옴 |
| 승리 | 180초 생존. 왼쪽 위 디지털 시계가 11:00에서 12:00까지 흐름. 레벨과 상관없이 같음 |

같은 프레임에 여러 조건이 겹치면 발각, DM 10단계, 승리 순으로 판정합니다. 히든 엔딩 연출이 시작되면 시간이 멈추고 다른 종료 조건은 판정하지 않습니다.

### main.gd의 역할

| 시점 | 동작 |
| --- | --- |
| `_enter_tree()` | `GameState.start_game()`. 자식 씬의 `_ready()`보다 먼저 호출되어, UI가 초기화된 값을 읽음 |
| `_ready()` | 배경색 설정, `game_ended` 연결, `TopView.npc_added`를 `AudioDirector.attach_npc`에 연결한 뒤 `TopView.spawn_npcs(TopView.npc_count())`로 사람 생성, `GameState.npc_total` 설정(무한 모드는 0) |
| `_process()` | `GameState.tick(delta, TopView.nearest_npc_distance())` |
| `_unhandled_input()` | `open_phone`, `debug_toggle`, `debug_add_stage`, `debug_clear_stage`, `debug_next_level`(디버그 모드에서 다음 레벨로 바로 이동. 레벨 1 → … → 9 → 테스트 맵(레벨 0) → 1 순서) |
| `game_ended` 수신 | `get_tree().paused = true` |

## GameConfig (A, B)

모든 조정값은 이 파일에 있으며 전부 플레이테스트 전 임시값입니다. 난이도별 값은 `LEVELS`에 두어, 이후 레벨을 항목 추가만으로 늘릴 수 있게 합니다. 아래는 현재 파일 전체입니다.

```gdscript
# res://scripts/game_config.gd
class_name GameConfig
extends RefCounted
## 모든 조정값. 전부 플레이테스트 전 임시값이다.
## A와 B는 각자 표시된 구역의 값만 수정한다.

# ===== A 구역 =====
# 맵(방·벽·문·소품 배치)은 레벨마다 scenes/top_view/levels/level_N.tscn에서 편집한다.
const CAMERA_ZOOM: float = 2.0                # 2 = 카메라 뷰 가로·세로 절반 (1920×1080 화면에 960×540이 보임)
const WALL_THICKNESS: float = 48.0
const BACKGROUND_COLOR: Color = Color(0.0, 0.0, 0.0)   # 맵 바깥. 벽 타일의 검정과 같게 한다

const PLAYER_RADIUS: float = 19.2
const PLAYER_SPEED: float = 144.0
const PLAYER_COLOR: Color = Color(0.85, 0.85, 0.8)
const CHARACTER_TURN_SPEED: float = 14.0      # 캐릭터가 이동 방향으로 도는 속도(라디안/초)
const CHARACTER_ANIM_BASE_SPEED: float = 60.0 # 걷기 애니메이션을 기본 속도(초당 12.5프레임)로 재생할 이동 속도. 빠를수록 비례해 빨라짐
const INTERACT_RANGE: float = 57.6

const NPC_RADIUS: float = 19.2
const NPC_SPEED: float = 86.4          # 플레이 피드백: 조금 더 빠르게 (57.6 → 86.4)
const NPC_AGGRO_SPEED: float = 172.8   # 115.2 → 172.8
const NPC_IDLE_TIME_RANGE: Vector2 = Vector2(1.0, 3.0)
const NPC_MAP_MARGIN: float = 72.0
const NPC_ARRIVE_DISTANCE: float = 9.6
const NPC_STUCK_TIMEOUT: float = 1.5
const NPC_SPAWN_MIN_DIST: float = 240.0      # 맵 절반에 맞춰 480 → 240
const NPC_SPAWN_SPACING: float = 64.0        # 처음 놓을 때 사람끼리 떨어뜨리는 거리 (지름 38.4 + 여유)
# 사람끼리는 몸이 부딪혀 겹치지 않는다. 걷는 사람은 가까운 사람을 미리 피해 옆으로 비켜 간다.
const NPC_AVOID_RADIUS: float = 64.0         # 이 거리 안의 사람을 피한다 (중심 거리)
const NPC_AVOID_STRENGTH: float = 1.2        # 피하는 힘. 클수록 일찍, 크게 비켜 간다
# 방마다 사람 수. 방의 기본 인원 = 넓이 / AREA_PER_NPC (반올림, 최소 1). 큰 방 960×720 = 6명, 작은 방 480×528 = 2명.
# 판의 사람 수 = 방 기본 인원의 합 + 레벨의 npc_bonus. 추가 인원은 기본 인원 비율로 방마다 나눠 목표 인원(할당량)이 된다.
const AREA_PER_NPC: float = 115200.0
const CROWD_MARGIN: int = 2                  # 방 인원이 목표 인원보다 이만큼 이상 많으면 다른 방으로 보낸다
```

### 긴장도와 손 떨림

긴장도는 v1 공식을 그대로 씁니다. 손 떨림은 v2부터 긴장도 대신 별도 근접도를 씁니다. 긴장도는 내려갈 때 초당 0.5씩 천천히 줄어서, 사람이 멀어져도 한동안 떨림이 남아 거리를 구분하기 어려웠기 때문입니다.

```text
긴장도 목표 = 0.7 × clamp(inverse_lerp(260, 80, 최근접 거리)) + 0.3 × (DM 단계 / 10)
              오를 때 초당 3.0, 내릴 때 초당 0.5로 따라감

근접도 목표 = clamp(inverse_lerp(520, 80, 최근접 거리))
              오를 때 초당 4.0, 내릴 때 초당 2.0으로 따라감
떨림 폭(px)  = 3 + 6 × (DM 단계 / 10) + 50 × 근접도²
떨림 속도    = 60 + (220 − 60) × 근접도²
```

헤드리스 측정값 (DM 0단계, 휴대폰 켠 상태, 각 거리에서 1.5초 측정):

| 최근접 거리 | 근접도 | 떨림 폭 | 실제 최대 이동 | 초당 이동량 |
| --- | --- | --- | --- | --- |
| 600px 이상 | 0.00 | 3.0px | 3px | 20px |
| 450px | 0.16 | 4.3px | 4px | 30px |
| 350px | 0.39 | 10.5px | 9px | 90px |
| 250px | 0.61 | 21.8px | 20px | 235px |
| 180px | 0.77 | 32.9px | 36px | 462px |
| 130px | 0.89 | 42.3px | 44px | 751px |
| 100px | 0.95 | 49.2px | 52px | 863px |

사람이 다시 600px 밖으로 나가면 0.5초 안에 3px로 돌아옵니다. v2.3에서 맵이 절반이 되었지만 떨림 거리(520px)는 그대로이므로, 사람들이 가까이 있는 경우가 많아 떨림이 더 자주 커집니다.

### 레벨

화면에는 Level 1\~9로 나오고, 코드의 `level_index`는 `GameConfig.LEVELS` 안의 순서라 1 작습니다(레벨 1 = 0). 맵 씬은 그 맵을 처음 쓰는 레벨 번호로 이름을 붙였습니다(`level_1`, `level_4`, `level_7`). 레벨 0은 테스트 맵이며 값은 `GameConfig.TEST_LEVEL`에 따로 있습니다. 메뉴의 레벨 선택과 다음 레벨에는 나오지 않고, 디버그 모드(F1)에서 F4로 레벨 9 다음에 갑니다. 레벨별 수치는 v2.7 변경 요약의 표를 봅니다. `TopView`가 시작할 때 `cfg['scene']`의 씬을 불러 맨 아래에 깔고, 플레이어를 그 씬의 `PlayerStart`에 놓습니다.

- `level_2.tscn`은 v2.7부터 쓰지 않습니다(레벨 2는 `level_1`을 씀).

### 사람 종류

레벨의 `npc_kinds`에 종류별 인원을 적으면 그만큼 배치하고, 나머지는 일반입니다. 예: `{'active': 1, 'tracker': 1, 'attention': 1, 'interactive': 1}`. 현재 레벨 0\~2는 모두 `{}`(일반만)입니다.

| 종류 | 행동 | 값 (GameConfig) |
| --- | --- | --- |
| 일반 `normal` | 위 기본 행동만 | |
| 활발형 `active` | 모든 이동이 1.5배 빠름. 쉬는 시간 0.3\~1초(일반 1\~3초). 걷는 중에도 0.8\~2초마다 새 목적지로 방향을 바꿈 | `ACTIVE_*` |
| 추적형 `tracker` | 15\~45초마다(v2.6, 10\~30초에서 빈도 2/3) 최대 6초 동안 플레이어를 따라옴(따라오기와 같은 108px/s, 80px 안에 들어오면 멈추고 끝냄). 시작할 때 머리 위에 "?" | `TRACKER_*` |
| 주의 집중형 `attention` | 30\~45초마다 480px 안의 사람들을 8초 동안 자기 주위(±70px)로 부르고 자신은 제자리에 섬. 머리 위에 "!". 문이 닫힌 방의 사람은 오지 않음 | `ATTENTION_*` |
| 상호작용형 `interactive` | 50\~70초마다 재사용 대기가 아니고 갈 수 있는 소품 하나로 걸어가 48px 안에 오면 작동. 머리 위에 "♪". 15초 안에 못 가거나, 그새 누가 쓰거나, 어그로·따라오기로 끊기면 5초 뒤 다시 시도 | `INTERACTIVE_*` |

- 특수 행동은 대기·걷기 중에만 시작하고, 다른 행동 중이면 끝날 때까지 미룹니다. 슬로우 댄스 중에는 하지 않습니다.
- 생김새는 종류와 상관없이 무작위라 그림으로는 종류를 구분할 수 없습니다. `NPC_KIND_COLORS`는 NPC 이미지가 없을 때의 임시 그림에만 쓰입니다. 디버그 모드에서는 머리 위에 종류 글자(활, 추, 주, 상)가 보입니다.
- `follower_option`은 일반 사람에게만 켭니다.
- 헤드리스 측정(v2.3 값, 레벨 2에 종류별로 1명씩 넣고 150초씩 3회): 활발형 최고 속도 259px/s(어그로 172.8 × 1.5), 걷는 중 목적지 변경 분당 38\~49회(일반 10\~12회). 추적형 시작 간격 11\~30초(슬로우 댄스 동안은 멈춤). 주의 집중형 호출 간격 37\~62초(슬로우 댄스 포함), 호출 때 반경 안 사람 전원이 모임. 상호작용형은 판마다 소품을 1\~2회 작동.

### 소품

위치와 어그로 지점(`aggro_offset`, 소품 기준 상대 좌표)은 각 레벨 씬의 소품 노드에서 편집하고, 이름·반경·재사용 대기·색은 `GameConfig.PROPS`에서 정합니다. 아래 좌표는 테스트 맵(레벨 0) 기준이며, 레벨 1은 소품이 같고, 레벨 2는 조명의 어그로 지점과 반경(소품 노드의 `radius_override`)만 다릅니다.

| 소품 | 위치 | 어그로 지점 (aggro\_offset) | 효과 반경 | 재사용 대기 | 플레이 용도 |
| --- | --- | --- | --- | --- | --- |
| 스피커 | (160, 160). 그림 긴 변 110px | 스피커 앞 (0, 0) | 320px | 30초 | 주변 사람을 스피커로 모아 다른 구역을 비움 |
| 조명 | (800, 16), 위쪽 벽에 붙음. 그림 긴 변 96px | (800, 560) (0, 544). 레벨 2: 작은 방 가운데 (1248, 360) (448, 344) | 360px. 레벨 2: 800px(큰 방 가운데까지) | 30초 | 스위치에서 먼 구역으로 사람을 유도 |
| 플레이리스트 | (480, 660). 그림 긴 변 150px | 무대 (480, 80) (0, −580) | 소품이 있는 방 전체(v2.9, `whole_room`) | 60초 | 그 방 사람을 모두 무대로 모음 |

안내 문구는 사용 가능할 때 "[E] Speaker", 재사용 대기 중에는 "Speaker: wait Ns"입니다.

소품 이미지 크기는 `GameConfig.PROPS`의 `icon_size`(긴 변)로 정합니다. 재사용 대기 중에는 `COOLDOWN_TINT`(0.25배, v2.6)로 어둡게 하고, 그림 아래에 줄어드는 막대(`CooldownBar`)와 남은 초(`CooldownLabel`)를 표시합니다. 둘 다 `prop.tscn`에서 `z_index` 10이라 소품으로 모인 사람에게 가려지지 않습니다. 상호작용 판정은 그림 크기의 사각형이고(플레이어 범위 57.6px), 몸체 충돌은 그림 크기의 85%입니다. 조명은 계기판(`prop_light_panel.png`), 플레이리스트는 DJ 턴테이블, 스피커는 `prop_speaker.webp` 이미지입니다. 맵별 소품 위치는 레벨 절의 표에 있습니다. 무한 모드의 소품은 `single_use`가 켜져 한 번 쓰면 사라집니다. 플레이리스트처럼 `whole_room`인 소품은 반경 대신 `PartyLevel.gather_area()`(소품이 있는 방, 무한 모드는 소품 가운데 960×720)의 사람만 모읍니다(v2.9). 조명은 자식으로 춤추는 자리(`DanceSpot`, 어그로 지점)를 만듭니다(v2.9).

### 글자 버튼 간격 (v2.3, v2.8에서 바꿈)

v2.8부터 열 수는 `letter_gap`을 지키며 영역 폭에 들어가는 만큼(3\~4열), 줄 수는 풍선 수 × `letter_spread` ÷ 열 수(모두 들어가는 최소 줄 수\~6줄)입니다. 레벨별 측정은 v2.8 변경 요약에 있습니다. 아래는 v2.3 때의 측정입니다.

헤드리스 측정(버튼 84×64, 영역 404×640):

| 레벨 | `letter_gap` | 가장 가까운 두 버튼 사이 | 버튼 무리 크기 |
| --- | --- | --- | --- |
| 0 | 40px | 13\~26px | 약 404×585 |
| 1 | 20px | 12\~15px | 약 397×493 |
| 2 | 8px | 6\~7px | 약 360×424 |

휴대폰 화면이 좁아 가로 간격은 레벨 0에서도 약 23px가 최대입니다. 그래서 레벨 0과 1의 차이는 주로 세로에서 납니다.

### 손 떨림

`PhoneView._update_tremor()`가 매 프레임 손 이미지와 실제 마우스 커서를 같은 양만큼 옮기고, `PhoneRoot`는 다른 노이즈 구간으로 옮깁니다. 휴대폰이 커서와 같은 패턴으로 움직이면 커서와 버튼 사이 거리가 변하지 않아 오히려 누르기 쉬워지기 때문입니다.

| 대상 | 폭 |
| --- | --- |
| 손, 커서 | `get_tremor_px() × 1.6` |
| 휴대폰 (본체, 버튼, 전원 판정 포함) | `get_tremor_px() × 1.6 × TREMOR_PHONE_RATIO(0.5)` |

노이즈 진행 속도는 `get_tremor_ratio()`에 따라 60에서 220으로 바뀝니다. 커서는 지난 프레임과의 차이만큼만 옮기므로 플레이어의 마우스 조작은 그대로 유지됩니다. 커서는 정수 픽셀 단위로 추적해 오차가 쌓이지 않으며, 휴대폰을 끄면 원래 자리로 돌아옵니다. 게임 창에 포커스가 없으면 커서를 옮기지 않습니다. 공식은 GameState 절을 참고합니다.

### 켜기와 끄기 전환

`PhoneView._update_slide()`가 진행도 0\~1을 `PHONE_SLIDE_SEC`(0.45초)에 걸쳐 바꿉니다. 휴대폰과 손은 `PHONE_SLIDE_DISTANCE`(1100px) 아래에서 움직이며, 자리에 가까울수록 느려집니다(`거리 × (1 − 진행도)³`). 배경 투명도는 진행도와 같습니다. 진행도가 0이 되면 `visible = false`가 됩니다. 히든 엔딩에서는 휴대폰이 내려가면서 둘러싼 사람들이 드러납니다.

### 여자친구 메시지

휴대폰을 켠 동안 화면 위쪽에 여자친구 메시지 알림(`GirlfriendBanner`)이 뜹니다. 켠 뒤 1.5초에 첫 메시지, 이후 5\~10초 간격이고, 3초 동안 보입니다. 누르면 바로 사라집니다. 문구는 `GIRLFRIEND_MESSAGES`이며 점수와 승패에는 영향이 없습니다. 제시 단어와 알파벳 버튼은 가리지 않습니다.

### 숨은 입력

`GameConfig.LETTER_COMBOS`에 정의합니다. 휴대폰이 켜져 있을 때의 키보드 입력(물리 키)과 글자 버튼 클릭을 하나의 기록으로 판정합니다. 키보드는 답장 진행에는 영향을 주지 않습니다. 발동하면 기록을 비우고, 휴대폰을 끄면 기록이 사라집니다.

| 설정 | BGM, 효과음 슬라이더(0\~100%). 바꾸는 즉시 적용하고 저장. 0이면 음소거 |

왼쪽 버튼은 항상 레벨 선택입니다. 컷 이미지는 각 컷의 사각 범위에 맞춰 늘리고 사선 모양으로 잘립니다. 이미지가 없으면 번호만 있는 빈 컷으로, 도장 이미지가 없으면 코드로 만든 임시 도장으로 표시합니다. 화면 이동은 `SceneFlow`에 모았습니다.
