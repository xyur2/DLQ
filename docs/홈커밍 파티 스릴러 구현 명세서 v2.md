# 홈커밍 파티 스릴러 구현 명세서 v2

Nov 7, 2026 · v1(Nov 6, @유리)에 플레이 피드백과 구현 중 결정을 반영한 개정판

A는 시스템과 탑뷰를, B는 휴대폰 뷰와 UI·연출을 맡으며, 두 파트는 `GameState` 오토로드로만 통신합니다. v1은 코드를 문서에 모두 실었지만, 이제 코드가 저장소에 있으므로 v2는 규칙, 구조, 계약, 수치를 기준으로 삼습니다. 코드와 이 문서가 다르면 이 문서를 고치거나 팀에 알립니다.

> **검증 상태:** 기준 코드는 `v2-feedback` 브랜치의 커밋 `ece5304`입니다. Godot 4.2.1 헤드리스 환경에서 자동 테스트로 규칙 동작을 확인했습니다. Godot 4.7 에디터에서 실제 마우스로 플레이하며 확인해야 할 항목은 마지막 절에 따로 적었습니다.

## v1 대비 변경 요약

| 항목 | v1 | v2 | 이유 |
| --- | --- | --- | --- |
| 씬 구성 | `main.tscn` 하나, 나머지 노드는 코드로 생성 | 탑뷰, 휴대폰, UI 씬으로 분리. 배치와 모양은 씬에서 편집 | 플레이 피드백: 유지보수 |
| 시작·종료 화면 | 코드로 생성 | `intro_screen.tscn`, `end_screen.tscn` | 플레이 피드백 |
| 답장 방식 | 번호가 붙은 버블 4개를 순서대로 클릭 | 제시된 단어의 알파벳을 순서대로 클릭. 단어에 없는 알파벳이 섞여 있음 | 플레이 피드백 |
| 오답 처리 | 제한 시간 0.5초 감소, 빈 곳 클릭도 오답 | 1초 동안 터치 잠금. 빈 곳 클릭은 무시 | 플레이 피드백 |
| 답장 제한 시간 | 10초, 끝나면 단계 +1 | 없음. 답장 실패 규칙 삭제 | 플레이 피드백 |
| 손 떨림 | `24 × 긴장도²`만큼 휴대폰을 흔듦 | 가장 가까운 사람과의 거리로 폭과 속도가 크게 달라짐 | 플레이 피드백: 거리를 떨림으로 구분 |
| 전원 버튼 | 기본 버튼 스타일이라 어두운 배경에 묻힘 | 휴대폰 오른쪽 옆면의 빨간 버튼과 "전원" 라벨 | 플레이 피드백: 버튼이 안 보임 |
| NPC 속도 | 걷기 57.6, 모이기 115.2px/s | 걷기 86.4, 모이기 172.8px/s (1.5배) | 플레이 피드백 |
| 소품 배치 | `main.gd`에 좌표 하드코딩 | 위치는 `top_view.tscn`, 종류별 수치는 `GameConfig.PROPS` | 씬 분리 |
| 초기화 시점 | `Main._ready()`에서 `start_game()` | `Main._enter_tree()`에서 호출 | 자식 씬의 `_ready()`가 먼저 돌기 때문 |
| 안정성 보완 | 없음 | 게임 종료 중복 방지, 어그로 목적지를 맵 안으로 제한, NPC가 목적지를 지나치지 않게 속도 제한 | 구현 중 발견 |

마우스 커서를 흔드는 방식도 시도했지만, 플레이 피드백에 따라 빼고 휴대폰 흔들림으로 되돌렸습니다.

## 작업 규칙과 파트 분담

### 파트 분담

| B (유리) | 휴대폰 뷰, 단어 답장, 손 떨림 연출, HUD, 사운드, 인트로, 종료 화면, 문구·폰트·오디오·아트 | scenes/phone/\*, scenes/ui/\*, game\_config.gd(B 구역), phone\_view.gd, letter\_button.gd, phone\_hands.gd, game\_hud.gd, dm\_icon.gd, audio\_director.gd, intro\_screen.gd, end\_screen.gd |

v2에서 B 파트 파일 상당수를 A가 플레이 피드백에 따라 고쳤습니다(휴대폰, HUD, 인트로, 종료 화면). 유리가 변경 내용을 확인한 뒤, 이후부터는 다시 파일 소유권 규칙을 따릅니다. `message_bubble.gd`는 단어 답장으로 바뀌면서 삭제했습니다.

### 공동 작업 규칙

- **파일 소유권:** 상대 파트의 파일은 직접 고치지 않고 요청합니다. `game_config.gd`는 예외로, 각자 표시된 구역의 값만 수정합니다.
- **통신:** 파트 간 직접 참조를 금지합니다. `GameState`의 시그널과 메서드만 사용하며, 시그니처 변경은 상의 후 진행합니다. `main.gd`는 세 씬을 묶는 역할만 합니다.
- **수치와 배치:** 밸런스 수치는 `GameConfig`에만 둡니다. 노드 배치, 크기, 색, 글자 크기 같은 모양은 각 씬(`.tscn`)에서 편집합니다.
- **문법:** Godot 4.3 이상, GDScript, 정적 타입을 사용합니다. 들여쓰기는 공백 4칸이며 파일 안에서 탭과 섞지 않습니다. Godot 에디터의 들여쓰기 설정(Editor Settings → Text Editor → Behavior → Indent → Type)을 Spaces로 맞춥니다.
- **씬:** 탑뷰, 휴대폰, UI를 각각 씬으로 나눕니다. 동적으로 생기는 것(NPC, 알파벳 버튼)만 코드에서 씬을 인스턴스합니다.
- **범위:** 이 문서에 없는 기능은 추가하지 않습니다. 애매한 부분은 가장 단순하게 구현하고 `# TODO(확인필요):`를 남깁니다.

## 게임 규칙

플레이어는 180초 동안 들키지 않고 DM을 10단계 미만으로 유지하면 승리합니다. 구현 중 규칙이 헷갈리면 이 절을 기준으로 삼습니다.

| 규칙 | 동작 |
| --- | --- |
| 스토리 | 주인공은 여자친구의 지인들로 가득한 홈커밍 파티에서 불륜녀에게 몰래 답장해야 함 |
| 발각 | 휴대폰이 켜진 상태에서 최근접 NPC가 80px 미만이면 즉시 게임 오버. 가까이 있을 때 켜도 동일 |
| DM 도착 | 15초마다 단계 +1. 휴대폰 상태와 무관 |
| DM 게임 오버 | 단계 10 도달 |
| 답장 시작 | 단계가 1 이상일 때 휴대폰을 켜면 단어가 제시됨. 켜 둔 동안 첫 DM이 와도 제시됨 |
| 답장 성공 | 제시된 단어의 알파벳을 순서대로 모두 누르면 단계 0으로 초기화 |
| 오답 | 다음에 눌러야 할 글자가 아닌 알파벳을 누르면 1초 동안 터치 잠금. 빈 곳 클릭은 아무 일도 없음 |
| 제한 시간 | 없음. 답장하지 않으면 DM이 계속 쌓일 뿐 |
| 전원 끄기 | 단어와 입력한 글자는 유지. 다시 켜면 이어서 입력 |
| 이동 | 휴대폰이 켜져 있으면 불가. NPC는 휴대폰 상태와 무관하게 계속 이동 |
| 상호작용 | 범위 안의 소품에 E. 휴대폰이 켜져 있으면 무시 |
| 승리 | 180초 생존. 왼쪽 위 시각이 11h 00에서 12h 00까지 흐름 |

같은 프레임에 여러 조건이 겹치면 발각, DM 10단계, 승리 순으로 판정합니다.

Godot 4.4 이상은 스크립트마다 `.gd.uid` 파일을 만듭니다. 스크립트와 함께 커밋합니다.

### project.godot

```ini
[application]
config/name="DLQ"
run/main_scene="res://scenes/main.tscn"

[autoload]
GameState="*res://scripts/game_state.gd"

[display]
window/size/viewport_width=1920
window/size/viewport_height=1080
window/stretch/mode="canvas_items"
```

- `window/stretch/aspect`는 생략했습니다. 기본값이 `keep`이라 v1과 같습니다.
- `[gui] theme/custom_font`는 폰트 파일이 들어오면 추가합니다. 그 전에는 OS 시스템 폰트로 한글을 표시합니다.
- `config/name`은 제목이 정해질 때까지 저장소 이름 `DLQ`를 씁니다.

### 씬 트리

```text
Main (Node2D, main.gd)                           scenes/main.tscn
├─ TopView (top_view.tscn, top_view.gd)
│  ├─ Map (Node2D, party_map.gd)
│  ├─ Props
│  │  ├─ Speaker  (prop.tscn)  prop_id = speaker
│  │  ├─ Light    (prop.tscn)  prop_id = light
│  │  └─ Playlist (prop.tscn)  prop_id = playlist
│  ├─ NPCs                                       ← spawn_npcs()가 npc.tscn을 넣음
│  └─ Player (player.tscn, party_player.gd)
│     ├─ CollisionShape2D
│     ├─ InteractionArea (Area2D) ─ CollisionShape2D
│     ├─ Camera2D
│     └─ AudioListener2D
├─ AudioDirector (Node, audio_director.gd)
├─ PhoneLayer (CanvasLayer, layer 20)
│  └─ Phone (phone.tscn, phone_view.gd)
└─ UI (ui.tscn)
   ├─ HudLayer (CanvasLayer, layer 10) ─ Hud (hud.tscn) ─ Clock, Hint, DmIcon ─ Badge
   ├─ ScreenLayer (CanvasLayer, layer 30) ─ IntroScreen, EndScreen
   └─ DebugLayer (CanvasLayer, layer 40) ─ DebugOverlay
```

충돌 모양의 크기는 `GameConfig`에서 정하므로, 씬에는 빈 `CollisionShape2D`만 두고 스크립트가 `_ready()`에서 모양을 넣습니다.

### main.gd의 역할

| 시점 | 동작 |
| --- | --- |
| `_enter_tree()` | `GameState.start_game()`. 자식 씬의 `_ready()`보다 먼저 호출되어, UI가 초기화된 값을 읽음 |
| `_ready()` | 배경색 설정, `game_ended` 연결, `TopView.spawn_npcs()`로 NPC 생성 후 `AudioDirector.attach_npc()` 연결 |
| `_process()` | `GameState.tick(delta, TopView.nearest_npc_distance())` |
| `_unhandled_input()` | `open_phone`, `debug_toggle`, `debug_add_stage`, `debug_clear_stage` |
| `game_ended` 수신 | `get_tree().paused = true` |

### 입력

| 액션 | 입력 | 처리 위치 | 파트 |
| --- | --- | --- | --- |
| move\_up, move\_down, move\_left, move\_right | W, S, A, D | Player | A |
| interact | E | Player | A |
| open\_phone | Q (켜기 전용) | Main | A |
| 아이콘 클릭 | 마우스 왼쪽 | DmIcon | B |
| 알파벳 버튼, 전원 버튼 클릭 | 마우스 왼쪽 | PhoneView, LetterButton | B |
| 인트로 클릭 | 마우스 왼쪽 | IntroScreen | B |
| restart | R | EndScreen | B |
| debug\_toggle, debug\_add\_stage, debug\_clear\_stage | F1, F2, F3 | Main | A |

입력 액션은 `InputSetup.ensure_actions()`가 `physical_keycode`로 등록합니다(v1과 같음, 한글 자판 대응).

## GameConfig (A, B)

모든 조정값은 이 파일에 있으며 전부 플레이테스트 전 임시값입니다. 난이도별 값은 `LEVELS`에 두어, 이후 레벨을 항목 추가만으로 늘릴 수 있게 합니다. 아래는 현재 파일 전체입니다.

### 긴장도와 손 떨림

긴장도는 v1 공식을 그대로 씁니다. 손 떨림은 v2부터 긴장도 대신 별도 근접도를 씁니다. 긴장도는 내려갈 때 초당 0.5씩 천천히 줄어서, 사람이 멀어져도 한동안 떨림이 남아 거리를 구분하기 어려웠기 때문입니다.

```text
긴장도 목표 = 0.7 × clamp(inverse_lerp(260, 80, 최근접 거리)) + 0.3 × (DM 단계 / 10)
              오를 때 초당 3.0, 내릴 때 초당 0.5로 따라감

근접도 목표 = clamp(inverse_lerp(520, 80, 최근접 거리))
              오를 때 초당 4.0, 내릴 때 초당 2.0으로 따라감
떨림 폭(px)  = 3 + 6 × (DM 단계 / 10) + 50 × 근접도²
떨림 속도    = 60 + (220 − 60) × 근접도²
```

헤드리스 측정값 (DM 0단계, 휴대폰 켠 상태, 각 거리에서 1.5초 측정):

| 최근접 거리 | 근접도 | 떨림 폭 | 실제 최대 이동 | 초당 이동량 |
| --- | --- | --- | --- | --- |
| 600px 이상 | 0.00 | 3.0px | 3px | 20px |
| 450px | 0.16 | 4.3px | 4px | 30px |
| 350px | 0.39 | 10.5px | 9px | 90px |
| 250px | 0.61 | 21.8px | 20px | 235px |
| 180px | 0.77 | 32.9px | 36px | 462px |
| 130px | 0.89 | 42.3px | 44px | 751px |
| 100px | 0.95 | 49.2px | 52px | 863px |

사람이 다시 600px 밖으로 나가면 0.5초 안에 3px로 돌아옵니다.

### 공동 통합 테스트

- [x] 사람이 없는 곳에서 휴대폰을 켜고 단어를 입력하면 단계가 0이 됩니다.
- [x] 80px 안에서 휴대폰을 켜면 즉시 게임 오버입니다. 꺼진 상태에서는 게임 오버가 되지 않습니다.
- [ ] 휴대폰을 켠 채 사람이 다가오면 소리와 떨림이 커지다가 게임 오버됩니다. 떨림은 확인했고, 소리는 오디오 파일이 들어온 뒤 확인합니다.
- [x] 한 번도 답장하지 않으면 150초에 DM 게임 오버가 됩니다.
- [ ] 180초를 버티면 시각이 12h 00이 되고 승리합니다. 시각 계산은 확인했고, 전체 플레이는 직접 확인이 필요합니다.
